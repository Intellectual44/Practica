# Тест-кейсы типографии

Предусловие для сценариев с готовыми данными — первая локальная база с учебной выборкой. Действия, меняющие данные, выполняются на отдельной учебной базе или с новыми записями. Статусы выполнения заполняются по результатам проверки.

| ID | Требования | Действие | Ожидаемый результат |
|---|---|---|---|
| T01 | F01 | Войти действующим менеджером | Откроется журнал заказов с ролью менеджера |
| T02 | F01 | Ввести неверный пароль | Останется окно входа с сообщением об ошибке |
| T03 | F01 | Нажать «Выйти» | Откроется окно входа, прежний JWT отклоняется |
| T04 | F02 | Добавить сотрудника, затем повторить логин | Первая запись создана, повтор получает 409 |
| T05 | F02 | Закрыть вход сотруднику, проверить его доступ и снова разрешить | Во время блокировки вход и запросы запрещены |
| T06 | F03, F04 | Создать заказ с тиражом 1, затем 1 000 000 | Оба допустимых заказа имеют статус «Принят» |
| T07 | F03 | Ввести 0 и 1 000 001 | Оба значения отклонены |
| T08 | F09 | Создать заказчика с именем длиной 150 символов и повторить с 151 | 150 принято, 151 отклонено |
| T09 | F04, F05 | Запустить печать без назначенного печатника, затем назначить | Первая попытка отклонена, повтор разрешён |
| T10 | F04, F12 | Согласовать заказ до заполнения макета и после | Переход возможен после заполнения поля |
| T11 | F06, F11 | Войти первым печатником, открыть таблицу и статистику | Отображаются назначенные ему заказы и показатели |
| T12 | F06 | Отметить свой тираж готовым, запросить чужой заказ по ID | Свой изменится, чужой запрос получит 404 |
| T13 | F07, F08 | Ввести «БРОШЮРА», выбрать «Готов», потом «Печать» | Число строк меняется при вводе и выборе статуса |
| T14 | F09 | Импортировать корректный и ошибочный CSV | Первый добавит заказчиков, второй вернёт номера строк без частичной записи |
| T15 | F10 | Сохранить выборку «Печать» во всех трёх форматах | CSV, JSON и XML содержат записи текущей выборки |
| T16 | F04, F11 | Попытаться выдать готовый тираж без суммы и даты, затем заполнить | После выдачи изменяются статистика и дата завершения |
| T17 | F04 | Отменить открытый заказ с пустой, затем заполненной причиной | Отмена проходит после заполнения причины |
| T18 | F03, F04 | Сохранить изменения с устаревшей версией через API | 409 и предложение обновить список |
| T19 | F12 | Открыть карточку заказа из выдачи | Карточка содержит тираж, параметры, макет, исполнителя и даты |

Матрица трассировки содержится в столбце «Требования». Матрица смены статусов приведена в [требованиях](requirements.md).

## Приёмочные сценарии

- Дано: менеджер открыл журнал. Когда он вводит «БРОШЮРА» и выбирает «Печать». Тогда видит назначенный тираж.
- Дано: печатник открыл назначенный заказ в печати. Когда подтверждает готовность. Тогда статус становится «Готов».
- Дано: администратор закрыл вход печатнику. Когда печатник отправляет запрос с действовавшим токеном. Тогда API возвращает 401.

## Чек-лист интеграции

- [ ] Открывается окно входа при F5.
- [ ] Вход доступен каждой роли.
- [ ] Ошибка пароля отображается в форме.
- [ ] Вкладка пользователей доступна администратору.
- [ ] Менеджер создаёт заказчика и заказ.
- [ ] Фильтр и поиск обновляют список при вводе.
- [ ] Карточка отображает параметры, тираж и макет.
- [ ] Условия переходов соблюдаются.
- [ ] Печатник видит назначенные заказы.
- [ ] Корректный CSV импортируется, ошибки выводятся по строкам.
- [ ] Форматы CSV, JSON и XML открываются с ожидаемыми полями.
- [ ] После перезапуска изменения сохранены.
