# Типография

Учебный проект УП.02, вариант 12. Приложение ведёт заказы на печатную продукцию от приёма до выдачи тиража.

## Запуск

1. В Visual Studio 2026 установите рабочие нагрузки «Разработка классических приложений .NET» и «Разработка ASP.NET и веб-приложений» с SDK .NET 10. Откройте `PrintingHouse.slnx`.
2. Нажмите **F5**. По умолчанию Visual Studio запускает `PrintingHouse.Desktop` с профилем «Типография». Если IDE сохранила предыдущий выбор проекта, откройте контекстное меню `PrintingHouse.Desktop` и выберите «Назначить запускаемым проектом».
3. Войдите под учебной учётной записью. База SQLite и демонстрационные заказы создаются при первом старте. Сервер запускается вместе с окном и связывается с клиентом по локальному HTTPS на случайном порту.

Для Visual Studio 2022 (17.8 и новее) с SDK .NET 8 используйте `PrintingHouse.sln`. Общие свойства сборки автоматически выбирают .NET 8 внутри VS 2022. Назначьте `PrintingHouse.Desktop` запускаемым проектом и нажмите **F5**. Основной целевой фреймворк решения — .NET 10. [Таблица совместимости Microsoft](https://learn.microsoft.com/dotnet/core/porting/versioning-sdk-msbuild-vs)

Для запуска вне IDE с SDK .NET 10 откройте терминал в папке решения и введите:

```powershell
dotnet run --project .\PrintingHouse.Desktop
```

Файл базы находится в `%LOCALAPPDATA%\PrintingHouse\printing-house.db`. Журналы API и WPF хранятся в подпапке `logs`.

Локальная сборка Debug восстанавливает пакеты без запроса аудита NuGet. Для Release и CI аудит включён.

## Рабочие места

| Роль | Учебный логин | Доступ |
|---|---|---|
| Администратор | `press.admin` | Заказы, заказчики, статистика, добавление сотрудников и управление входом |
| Менеджер | `press.manager` | Все заказы и переходы, заказчики, импорт, выгрузка, общая статистика |
| Печатник | `press.operator`, `press.operator2` | Назначенные заказы и своя статистика, отметка готовности тиража |

Учебные пароли передаются отдельно. Для проверки разграничения доступа два печатника получают разные демонстрационные заказы. Автоматизированные сценарии UI получают пароли через `PRINTINGHOUSE_DEMO_ADMIN_PASSWORD`, `PRINTINGHOUSE_DEMO_MANAGER_PASSWORD`, `PRINTINGHOUSE_DEMO_OPERATOR_PASSWORD` и `PRINTINGHOUSE_DEMO_OPERATOR2_PASSWORD`.

## Правила работы с ветками

Проект использует упрощённый Git Flow. В `develop` интегрируются изменения, а `main` хранит состояние выпусков, отмеченных тегами `v0.9.0` и `v1.0.0`. Разделение веток позволяет сохранить демонстрационную версию, пока в `develop` поступают исправления и материалы практики.

Задачу ведут в ветке `feature/<номер>-<название>`, дефект — в `fix/<номер>-<название>`. Запрос на слияние в `develop` ссылается на соответствующую задачу. Подготовленный выпуск попадает в `main` через отдельный запрос на слияние. Практика выполняется индивидуально.
